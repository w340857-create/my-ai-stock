# MY AI Stock 4.1.1

เว็บนับสินค้าและบันทึกรับเข้า ใช้บน GitHub Pages ข้อมูลเก็บในเบราว์เซอร์ของแต่ละเครื่อง ไม่ซิงก์ข้ามเครื่อง

## ทดลองรับเข้า

1. เปิดเมนู **รับสินค้าเข้า**
2. กด **ลองใบเก่า · ครบ 12 หน้า (345 บรรทัด)** โหลดครบ 12 หน้า รวม 345 บรรทัดตามเอกสาร สามารถกรองตามเลขหน้าได้
3. ตรวจรายการ แล้วกด **ทดลองกรอกครบตามใบ** เพื่อจำลองว่ารับครบ
4. กด **ยืนยันบันทึกรับเข้า** จะได้ 345 บรรทัด รวม 96 CAR, 261 PAC, 276 PC และ 3 SAC ในยอดทดลอง
5. กด **สำรอง JSON** เพื่อเก็บประวัติ ใบร่าง และรายการนับทั้งหมด

ตัวอย่างถูกจำกัดเป็นโหมดทดลอง ไม่มีข้อมูลลูกค้าหรือที่อยู่จากเอกสารเผยแพร่ในโค้ด ชื่อสินค้าบางรายการอ่านไม่ชัดและระบุให้ตรวจชื่อสูตร/ยี่ห้อก่อนใช้ รหัสและบาร์โค้ดคงเป็นข้อความเพื่อรักษาเลขศูนย์นำหน้า

## รับเข้าจริง

เริ่มใบใหม่ เลือก **รับเข้าจริง** กรอกเลขใบส่งของและวันที่ นำเข้า CSV ที่มีคอลัมน์ `name,code,barcode,expected,unit,pack_size` แล้วกรอกจำนวนรับจริงทุกแถว (ใส่ 0 หากไม่ได้รับ) ไม่เติมจำนวนรับจริงจากใบส่งของโดยอัตโนมัติ

- หน่วย CAR/PAC/SAC และหน่วยอื่นแยกกัน ไม่เดาจำนวนชิ้นต่อลัง
- รับชิ้นแยกได้เมื่อกำหนดจำนวนต่อหน่วยแล้ว
- ยอดรับเข้าสะสมแยกทดลอง/จริง ไม่รวมยอดตรวจนับ และยังไม่หักยอดขาย
- เลขใบส่งของซ้ำในโหมดเดียวกันถูกปฏิเสธ ข้ามตัวพิมพ์ใหญ่/เล็กและช่องว่าง
- ยกเลิกใบรับได้จากประวัติ ยอดของใบนั้นถูกหักออกและประวัติยังอยู่
- นำเข้า CSV เพื่อแทนที่ใบร่างเท่านั้น ยังไม่เพิ่มสต็อกจนยืนยัน
- การบันทึกที่ล้มเหลวจะไม่แจ้งว่าสำเร็จหรือเพิ่มประวัติบางส่วน
- เมื่อข้อมูลเปลี่ยนในอีกแท็บ ต้องรีเฟรชก่อนบันทึกต่อ

## สำรองและกู้คืน

JSON รุ่น 4.1 รวมรายการนับ ประวัติรับเข้า และใบร่าง รับไฟล์สำรองรุ่นเดิมได้ด้วย การกู้คืนเป็นการแทนที่ข้อมูลทั้งหมด ไม่ใช่บวกรวม ไฟล์เก่าจึงไม่มีประวัติรับเข้ารุ่นใหม่

ปุ่ม **ล้างเฉพาะยอดนับ** ไม่ลบประวัติรับเข้า ส่วน **ลบข้อมูลทั้งหมด** ลบทั้งข้อมูลนับ ใบร่าง และประวัติรับเข้าในเครื่องนี้หลังยืนยัน

## ตรวจสอบโค้ด

ใช้ Node.js 18 ขึ้นไป ไม่ต้องติดตั้งแพ็กเกจ:

```sh
node tests/receipt-data.cjs
node tests/receiving.cjs
```

ชุดตรวจสอบครอบคลุมย้ายข้อมูลเดิม โหมดทดลอง/จริง เลขใบซ้ำ การบันทึกล้มเหลว จำนวนรับจริง การรวมชิ้นแยก สำรอง/กู้คืน ยกเลิกใบ และ CSV ที่มีบาร์โค้ดขึ้นต้นศูนย์ การตรวจนี้จำลอง DOM; ต้องตรวจหน้าจอและกล้องบนเบราว์เซอร์จริงแยกต่างหาก


## ข้อมูลตัวอย่างครบ 12 หน้า

ไฟล์ `data/receipt-demo.js` เป็นรายการทดลองที่ถอดจากภาพสแกนทั้ง 12 หน้า มี 345 บรรทัด แสดง `sourcePage` และ `sourceRow` เพื่อเทียบกลับกับเอกสารได้ ตัวอักษร C หมายถึงหมวดลังเต็ม และ T หมายถึงหมายเลข Tote กับลำดับในตะกร้า

- หน้า 1–12 มี 18, 33, 28, 32, 31, 31, 31, 30, 30, 31, 31, 19 บรรทัดตามลำดับ
- หมวดลังเต็ม 56 บรรทัด รวม 101 หน่วยตามสรุปหน้าแรก (96 CAR + 2 PAC + 3 SAC)
- มี Tote ครบหมายเลข 1–35 ไม่ตัดรายการสินค้าซ้ำที่อยู่คนละตะกร้า
- ยอดรวมทั้งเอกสาร: 96 CAR, 261 PAC, 276 PC, 3 SAC ไม่แปลงหน่วยรวมกัน
- ผลรวมรายรหัสและหน่วยมี 337 รายการ การกรอกรับจริงและประวัติเก็บครบ 345 บรรทัดต้นฉบับ
- ตรวจหลักตรวจสอบ GS1 ของบาร์โค้ดครบทุกบรรทัดแล้ว ข้อนี้ตรวจความสมบูรณ์ของเลข ไม่ใช่ยืนยันว่าเป็นสินค้ายี่ห้อใด
- กำหนดจำนวนต่อลังเฉพาะน้ำแร่ 1500 ml = 8 และ 500 ml = 15 ที่ผู้ใช้ยืนยันแล้ว
- หากบันทึกตัวอย่าง 18 รายการหน้าแรกไว้ก่อนหน้านี้ การยืนยันใบตัวอย่างเต็มจะแจ้งยกเลิกใบตัวอย่างเดิมและเก็บประวัติไว้ เพื่อไม่บวกรายการซ้ำ การบันทึกกับยกเลิกทำพร้อมกัน และถ้าบันทึกล้มเหลวจะไม่เปลี่ยนยอดเดิม
- กดดาวน์โหลด CSV ทั้ง 12 หน้าได้จากหน้าเว็บ ไม่ต้องนำเข้าซ้ำหลังโหลดตัวอย่าง
